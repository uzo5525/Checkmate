# 레디고(ReadyGo) — 기획서 작성용 프롬프트

아래 내용을 바탕으로 기획서(PRD), 기능명세서, 유저플로우, 화면 목록을 만들어 줘.
"우선순위" 표기: P0 = 해커톤(11/1~11/5) 필수, P1 = 해커톤 중 가능하면, P2 = 출시 이후.
"검토 중"으로 표시한 항목은 팀이 아직 결정하지 않은 선택지야. 두 안을 비교해서 정리해 줘.

---

## 1. 프로젝트 개요
- 서비스명: 레디고(ReadyGo) — 해외여행 출발 전 D-day 준비 점검 앱 (Android)
- 팀: 여행의 숲 (개발 1, 디자인 1, 기획·비즈니스 2 / 연세대)
- 배경: SVC Seoul AI 해커톤 공모과제 ① "출발 전, D-day 점검 에이전트" 본선 진출
- 일정: 본선 개발 11/1~11/5, 목표 = Google Play 비공개 테스트 링크 배포 → 이후 정식 출시
- 현재 상태: 동작하는 프로토타입 APK 있음 (Expo React Native + Supabase). 디자이너 시안 4장(메인/함께 준비/짐 점검/서류 확인) 반영 완료

## 2. 해결하려는 문제
1. 여행지·국적별로 비자, 입국신고, eSIM, 환전, 보험, 반입 금지 품목 등 준비 정보가 흩어져 있고, 언제 무엇을 해야 하는지 알기 어렵다.
2. 동행이 있으면 개인 준비와 공동 준비가 섞이고, 메신저·메모로는 담당자와 완료 여부를 파악하기 어렵다. 장소·일정 의견도 대화에 흩어진다. 준비 부담이 주도하는 한 사람에게 몰린다.
3. 체크리스트에 "완료"를 눌러도 실제 조건에 맞는지는 모른다. (예: 보험 보장기간이 귀국일을 안 덮음, 여권 만료 임박, 보조배터리 용량 초과·위탁 금지, 100ml 초과 액체)

## 3. 타깃 사용자
- 항공권·숙소 예약을 마치고 출발 전 준비를 스스로 하는 자유여행객
- 친구·연인·가족 등 2~6명 소규모 동행 여행객, 특히 준비를 총괄하는 사람
- 해외여행 경험이 적거나 처음 가는 나라로 가는 사람
- 연령대보다 "체계적인 관리와 정확한 점검이 필요한 여행자"가 핵심

## 4. 핵심 가치 / 차별점
- "무엇을 준비할지"를 넘어 "출발할 준비가 제대로 됐는가"까지 확인
- AI 준비 에이전트: 여행 상태를 보고 오늘 할 일·놓친 위험·추가할 일·역할 분담을 먼저 제안 (과제명 "D-day 점검 에이전트"의 핵심)
- 개인 준비와 공동 준비를 분리해서 함께 관리 (담당자 지정, 실시간 공유)
- 판정 결과마다 근거 출처와 확인 날짜를 표시하고, 문제가 있으면 후속 조치까지 안내
- 개인정보 최소화: 여권 사진은 폰 밖으로 나가지 않음, 개인 서류는 동행자에게 비공개
- 경쟁 서비스 대비: Wanderlog·Tripsy(일정 공유 중심), TripIt(예약 통합), PackPoint(준비물 추천)는 출발 조건 검증과 개인/공동 준비 분리가 약함

## 5. 앱 구조 (하단 탭 5개)
홈 · 준비 · 스캔(짐 점검, 가운데 강조) · 동행 · MY
그 외 화면: 시작(내 여행 목록), 여행 만들기, 방 참여, 항목 상세, 설정

## 6. 기능 목록

### A. 여행 생성 & D-day 체크리스트 [P0]
- 입력: 여행지(국가), 국적, 출발일·귀국일(달력 선택), 인원, 닉네임
- D-30 / D-14 / D-7 / D-3 / D-1 시점별 체크리스트 자동 생성
- 필수 6항목 반드시 포함: 비자, 입국신고, eSIM, 환전, 여행자보험, 반입 금지 품목 (+ 여권 유효기간, 공항↔숙소 이동, 날씨, 짐 싸기 등)
- 체크리스트 데이터는 AI 생성이 아니라 공식 출처 기반 규칙 데이터 (항목별 출처 URL, 검증 여부 표시). 미검증 항목은 "공식 확인 필요" 표시
- "지금 할 일"과 "기한 지난 미완료"를 상단에 강조
- 개인 항목 직접 추가·수정 [P1]
- 지원 국가: 현재 일본 1개국 → 확장 [P0]
  - 검토 중: (안1) 10개국 = 일본·베트남·태국·중국·대만·필리핀·싱가포르·홍콩·미국·프랑스 / (안2) 5개국 = 일본·베트남·태국·대만·미국 (데이터 검증 부담 때문)
  - 데이터가 없는 국가: AI가 웹 검색으로 공식 출처를 찾아 요약하고 "AI 요약·공식 확인 필요" 표시 [P2]

### B. 공유 방 (함께 준비) [P0]
- 여행 생성 시 방 생성: 6자리 방 코드 + 초대 링크, 안드로이드 공유 시트로 전송
- 참여: 링크 또는 코드 입력 → 닉네임만 입력 (회원가입 없음, 내부적으로 익명 로그인)
- 체크리스트 구분
  - 개인 체크리스트: 여권, 보험, eSIM, 개인 짐 등. 동행자에게는 진행률만 공유하고 세부 항목은 비공개
  - 공유 체크리스트: 숙소, 공항 이동, 공용 준비물 등. 담당자 지정, 완료 여부 모두 공유
- 동행 현황: 멤버별 진행률
- 실시간 반영 (다른 멤버 체크가 즉시 반영)
- 방장 권한: 멤버 관리(내보내기), 공유 항목 추가·수정·삭제, 담당자 지정, 멤버에게 공유 편집 권한 부여
- 여행 정보 수정·삭제, 방 나가기, 방장 넘기기 [P1]

### C. 여행 코스: 지도 장소 투표 → 날짜별 일정 [P0]
- 장소 제안 방법 (모두 무료)
  1) 구글맵 앱에서 장소 공유 → 레디고 선택 → 바로 "투표에 올리기" (안드로이드 공유 대상 앱으로 등록)
  2) 구글맵 링크 붙여넣기 → 좌표·이름 자동 추출
  3) 지도를 길게 눌러 핀 직접 찍기 + 이름 입력
- 제안된 장소는 지도 핀으로 표시, 표가 많을수록 강조. 핀을 누르면 장소 카드에서 투표·투표 취소
- 투표 결과를 1일차·2일차… 일정에 배치 (방장 + 공유 편집 권한 멤버)
- AI 일정 자동 구성 → 아래 "I-2" 참고
- 날짜별 코스를 지도에 순서 번호 핀 + 연결선으로 표시, 아래에 일정 목록
- "구글맵에서 열기"로 길찾기 연결
- 제약: 앱 내 장소 검색 기능은 없음 (비용 문제, 정책 참고)

### D. 짐 점검 (비중 축소 — 보조 기능)
- 가방 전체 사진 AI 인식은 제외 (가방 속 물건은 사진에 다 안 보이고, 판정에 필요한 용량은 결국 따로 입력해야 해서 효용이 낮음)
- 수동 입력 판정 [P0, 현재 구현됨]: 보조배터리(mAh·전압 → Wh 자동 계산), 액체류(용기당 ml), 스프레이(종류·ml), 날카로운 물품(종류·날 길이), 식품(종류·도착국 검역)
- 결과 4단계: 기내 가능 / 위탁 가능 / 제한·금지 / 추가 확인 필요 + 출처·확인 날짜 + "항공사 공식 안내 확인" 문구
- 라벨 촬영으로 용량 읽기 [P1]: 보조배터리·화장품 라벨을 한 개씩 찍으면 폰 안 문자 인식으로 mAh·Wh·ml를 읽어 바로 판정 (무료, API 미사용)
- 짐 리스트 [P1]: 기본 리스트 + 항목 추가·삭제·수량 조절 + "가방에 넣음" 체크 + 저장 (날씨 연동은 P2)
- 탭 구조 검토 중: 짐 점검의 비중이 줄었으니 하단 가운데 "스캔" 탭을 다른 기능(예: AI 브리핑 또는 지도)으로 바꿀지

### E. 서류 확인 [P0, 축소 검토 중]
- 핵심은 "사진 읽기"가 아니라 "여행 일정과의 대조"
- 검토 중 (권장안 = 축소)
  - 여권: 폰 안 문자 인식으로 여권 하단 MRZ 두 줄을 읽어 영문 성명·만료일 추출 (체크 디지트 검증, 여권번호는 저장 안 함, 사진은 폰 밖으로 안 나감) → 목적지 유효기간 요건과 비교
  - 보험: 보장 시작일·종료일 2개만 입력 → 출국~귀국 전체를 덮는지 확인
  - 비자: 체크리스트 안내로만 처리 / 항공권: 제외 (여행 생성 때 날짜 입력함)
  - 별도 화면 대신 체크리스트의 "여권 유효기간", "여행자보험" 항목 안에서 바로 확인
- 결과 3단계: 정보 일치 / 추가 확인 필요 / 정보 불일치
- 문제가 있으면 후속 조치 안내 (예: 여권 → 외교부 여권안내 재발급, 보험 → 기간 연장·재가입) + 해결 전까지 해당 항목 미완료 유지
- 서류 정보는 이 기기에만 저장, 동행자 비공개, 삭제 가능

### F. 홈 [P0]
- 여행 제목 + D-day 배지, "출발까지 N일 · 준비할 일 N개 남음" 요약
- 빠른 메뉴: 체크리스트, 짐 점검, 여행 서류, 동행 초대
- 오늘 준비할 일 목록 (바로 체크)
- 함께 준비하는 동행 아바타
- 검토 중: 도시 사진 영역을 오늘 일정 지도로 대체

### I. AI 기능 (API 최소 사용 원칙)
원칙: 입국 요건·반입 규정 같은 "사실"은 공식 데이터와 규칙 코드로 처리하고, AI(LLM)는 판단·정리·개인화만 맡는다. 계산할 수 있는 것은 코드로 먼저 하고, LLM 호출은 여행당 하루 1~2회 수준으로 제한한다.

#### I-1. AI 준비 에이전트 [P0]
- 입력: 여행 상태 (남은 날짜, 미완료·기한 지난 항목, 멤버별 진행률, 확정된 일정, 도착 시간 등)
- 처리: 위험·후보 탐지는 규칙 코드로 먼저 (예: 귀국편 23시 이후 도착, 보험 미완료 D-5, 일정에 테마파크 포함) → LLM은 우선순위 판단과 자연어 정리만
- 출력
  - "오늘 할 일 3가지" 데일리 브리핑 (홈 상단)
  - 상황 맞춤 할 일 제안 (예: 일정에 유니버설 스튜디오 → "입장권 사전 예매" 추가 제안) → 사용자가 수락해야 체크리스트에 추가
  - 동행 역할 분담 제안 (예: 진행률 낮은 멤버의 공유 항목을 다른 멤버에게 넘길지)
- 비용 제어: 여행당 하루 1회 생성 후 저장해서 재사용, 사용자가 새로고침해도 일일 상한 내. API 잔액 소진·상한 초과 시 규칙 기반 문장으로 대체 (기능은 계속 동작)
- AI가 제안한 할 일에는 "AI 제안" 표시, 사실 정보는 기존 공식 데이터 출처를 그대로 연결

#### I-2. 투표 결과로 일정 자동 구성 [P0]
- 투표된 장소들의 좌표로 가까운 곳끼리 묶고 날짜 수에 맞춰 동선 초안 생성 (거리 계산·묶기는 코드로 처리, 유료 길찾기 API 미사용)
- LLM은 날짜별 테마 이름·짧은 설명·순서 다듬기만 (여행당 1회)
- 방장(또는 편집 권한 멤버)이 초안을 수정·확정 → 공동 일정에 반영

#### I-3. 폰 안 AI (무료, API 미사용)
- 여권 MRZ 인식, 라벨 용량 인식 (구글 ML Kit 문자 인식)

#### I-4. 이후 후보 [P2]
- 물품명 AI 분류 ("전자담배", "고데기" 등 아무 물품 → 규정 카테고리 분류, 판정은 규칙 데이터)
- AI 국가 정보 요약 (데이터 없는 나라, 웹 검색 + 출처, 나라별 1회 생성 후 모든 사용자 공유)
- AI 맞춤 짐 리스트

### G. 알림 [P1]
- D-30, D-14, D-7, D-3, D-1 시점별 로컬 푸시 (서버 비용 없음), 기한 지난 항목 리마인드

### H. MY / 설정 [P0]
- 내 정보, 내 여행 서류, 다른 여행 보기
- D-day 시뮬레이터 (시연용: 오늘 날짜를 바꿔 시점별 화면 변화 확인)

## 7. 정책

### 개인정보
- 여권 이미지·여권번호·생년월일은 저장·전송하지 않음 (폰 안 처리)
- 개인 서류 정보는 기기에만 저장, 동행자 비공개, 사용자가 삭제 가능
- 개인 체크리스트는 진행률만 공유
- AI 에이전트에는 서류 내용·개인정보를 보내지 않고, 체크리스트 상태·날짜·일정 같은 여행 정보만 보냄
- 개인정보처리방침 공개 페이지 필요 (스토어 필수)

### 비용 안전장치 (1원이라도 예상 밖 지출 차단)
- 구글 지도: 지도 표시(맵 ID 없는 기본 방식, 무료)만 사용. 장소 검색·지오코딩·길찾기 등 유료 API는 사용하지 않음. 키는 우리 앱 전용으로 제한, 일일 사용량 상한, 예산 감지 시 결제 자동 차단
- AI(Claude API): 최종 목표는 API 최소 사용. 선불 충전 + 자동 충전 꺼짐, 서버(Edge Function)에서만 호출 (키는 앱에 넣지 않음), 결과 저장·재사용, 여행당·전체 일일 상한, 잔액 소진 시 규칙 기반으로 대체
- DB(Supabase): 무료 플랜 유지
- 악의적 사용: 사용자별·앱 전체 상한 → 최악의 경우 기능 일시 중지, 요금 발생 없음

### 데이터 신뢰
- 입국 요건·반입 규정은 AI가 만들어내지 않음. 공식 출처 기반, 항목별 출처·확인 날짜·검증 여부 표시
- 미검증 데이터는 "초안·공식 확인 필요" 경고

## 8. 수익 모델
- 무료: 체크리스트, 공유 방, 지도 투표·수동 일정, 짐 판정, 여권·보험 확인, 기본 AI 데일리 브리핑 (API 호출 최소 → 무료 사용자 비용 거의 0)
- 프리미엄 (P2에 결제 연결, 해커톤에서는 "체험 N회 무료"로 시연): AI 일정 자동 구성, AI 할 일·역할 분담 제안 등 고급 에이전트 기능, (향후) AI 짐 리스트·국가 정보
  - 예: 여행 1건 프리미엄 2,900원 (구글 수수료 15% 제외 약 2,460원), AI 호출은 여행당 몇 회 수준이라 비용이 매우 작음
- 제휴 수수료 (P2): 체크리스트 항목에서 eSIM·환전/트래블카드·현지 교통패스 구매 연결. 여행자보험은 보험업법상 정식 제휴 채널로만
- B2B (P2): 여행사·항공사에 출발 전 점검 도구 제공

## 9. 기술 스택 / 제약
- Expo (React Native) + TypeScript, expo-router, Zustand / Android 우선
- Supabase: DB, 실시간 동기화, 익명 로그인, 보안 규칙(RLS), Edge Functions(AI 프록시·사용량 제한)
- AI: Claude API (Edge Function 경유, 에이전트 브리핑·일정 구성에만, 결과 캐시), 폰 안 문자 인식(ML Kit)으로 여권 MRZ·라벨 용량
- 지도: Google Maps SDK for Android (맵 ID 없이 사용, 유료 API 미사용)
- 디자인: 블루·네이비 톤, 원형 체크, 하단 5탭, 토큰·UI 컴포넌트 분리 구조 (디자이너 시안 교체 용이)
- 빌드·배포: EAS Build → APK(테스트), AAB(Google Play)

## 10. 성공 지표 (예시)
- 해커톤: 핵심 시나리오 시연 성공 (방 생성 → 동행 참여 → 실시간 체크 → 지도 투표 → AI 일정 자동 구성 → AI 데일리 브리핑·할 일 제안 → 보험 기간 불일치 감지), Play 비공개 테스트 링크 배포
- 출시 후: 여행당 체크리스트 완료율, 동행 초대율(여행당 참여 인원), AI 제안 수락률, 출발 전 발견된 문제 건수(보험·여권·반입 금지), 프리미엄 전환율, D-1 재방문율, 여행당 API 비용
